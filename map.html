GitLab 做的事可以一句話講完：一個產品把整個 DevOps 生命週期包起來—— 從程式碼到部署、監控，全部內建。下面從「基礎」到「比較」拆解。

1. 基礎：專案與群組 · Projects & Groups

一切從「專案」開始（單元 1、單元 2）。

GitLab一體化 DevOps 平台 自架CE / EE 安裝於自家 Project專案（=repo） Group群組組織專案

2. 協作：Merge Request · MR

GitLab 的合併請求流程（單元 3、單元 4）。

分支Branch MRMerge Request 合併請求 衝突Conflict 處理 Approvals批准機制
Code Review逐行審查 保護分支強制 MR 才能合併 關聯Closes #issue

3. DevOps 內建：Issues / CI/CD / Pages

GitLab 的最大特色——全都內建在同一產品（單元 5、單元 6、單元 7）。

Issues任務與 bug Boards看板管理 CI/CD內建 pipeline Pages靜態網站

4. 比較：GitLab vs GitHub

本課重點：全面對比與選型（單元 8）。

術語對照MR vs PR 託管模式自架 vs 公有雲 CI/CD內建 vs Actions 選型建議哪個適合你
小結：GitLab = 「一個產品包辦 DevOps」×「可完全自架」。 學會它，你不只會用一套工具，更能理解「GitHub 之外」的世界長什麼樣。
