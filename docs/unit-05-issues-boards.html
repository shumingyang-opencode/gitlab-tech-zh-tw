單元 5 · Issues 與專案管理

任務、分類、里程碑與看板 — Issues & Boards

GitLab 的專案管理與 GitHub 概念相近，但有些獨特設計—— 尤其 Issue Boards 與 Milestones 的整合很深。

Issues · 任務與 Bug

與 GitHub 相同：一件事一張單、有編號（#12）、可留言與指派。

Issue 寫法 · FORMAT
標題：登入頁在 Safari 上空白
描述：
  步驟：
  1. 開 Safari 到 /login
  2. 畫面空白
  預期：顯示表單
  環境：Safari 17

Labels · 標籤

內建常用的預設標籤，也可自訂：

常見標籤 · LABELS
bug  feature  documentation
good first issue  help wanted
priority::high    # GitLab 支援「scope::」命名

GitLab 建議用 type::、priority:: 字首統一標籤命名（「scoped labels」）。

Milestones · 里程碑

把 issue / MR 歸到一個里程碑，追蹤整體進度。

Milestone 範例 · EXAMPLE
v1.0 發布（2026-10-01）
  ├─ #10 修登入 bug（open）
  ├─ #12 新增搜尋（open）
  └─ #15 文件（closed）
  進度：1/3
特色：GitLab 的 Milestone 同時掛 issue 與 MR——合併的 MR 會自動算進進度， 對齊「這個版本做了什麼」。

Issue Boards · 看板

類似 GitHub Projects 的看板，但更接近 Trello：以 label 或 milestone 定義欄位。

看板 · BOARD
┌─ To do ──┬─ Doing ──┬─ Review ──┬─ Done ──┐
│ #10      │ #12       │           │ #15     │
└──────────┴───────────┴───────────┴──────────┘
欄位通常對應 label：do::1 / do::2 / review / done
進階：可建立多個 board（依產品、依團隊）、 加「wip limit」（進行中數量上限）——比 GitHub Projects 更「工程團隊」導向。

Epics · 史詩

群組層級的「大目標」，底下掛多個 issue——GitLab 特有（EE/付費才有完整功能）。

Epic 範例 · EXAMPLE
Epic：2026 上半年使用者體驗
  ├─ #20 新版登入
  ├─ #21 暗色模式
  └─ #22 載入動畫

Wiki · 文件

每個專案內建 Wiki（Markdown），適合長文件。跟 GitHub 的 Wiki 定位相同。

完整工作流

工作流 · WORKFLOW
1. 開 Issue（含 label 與 milestone）
2. 開分支 → 開發 → 開 MR（Closes #12）
3. CI 跑（單元 6）→ 有人 Approve
4. 合併 → Issue 自動關閉、看板自動移動
看完這頁你應該能說出：
  • Issue、Label、Milestone 的基本用法。
  • GitLab 的 scoped labels 命名習慣。
  • Issue Boards 與 Epic 的特色。
  • Issue → MR → Closes 的完整循環。
