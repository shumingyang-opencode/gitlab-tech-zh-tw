7.1 GitLab Pages 是什麼

GitLab Pages 把專案裡的靜態檔案直接變成網站——與 GitHub Pages 概念相同， 但部署完全由 CI/CD 驅動：你寫一個特殊的 pages job，GitLab 就把產出發布成網站。

一句話：Pages = 「CI 的產出 → 靜態網站」。所以它跟單元 6 密不可分—— 先懂 pipeline，Pages 就只是「其中一種 deploy job」。

7.2 URL 格式

部署後的網址 · URLS
專案頁（GitLab.com）：
  https://USER.gitlab.io/project-name/

使用者頁：
  https://USER.gitlab.io/
  （專案名必須是 USER.gitlab.io）

群組頁：
  https://GROUP.gitlab.io/
  （或 https://GROUP.gitlab.io/project/）

自架：
  https://pages.example.com/project/

7.3 啟用 Pages：pages job 三步驟

GitLab 找「名叫 pages 的 job」來發布網站，且 stage 固定 deploy，內容放 public/：

.gitlab-ci.yml · 純靜態站
pages:
  stage: deploy
  script:
    - mkdir -p public
    - cp -r index.html assets public/
  artifacts:
    paths:
      - public
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
三步驟：（1）job 名 pages；（2）把網站內容放進 public/；（3）用 artifacts 把 public 傳出去。pipeline 成功後 GitLab 自動發布。

7.4 需要建置的專案（框架）

用 Node 建置工具（Vite / Astro / Hugo）時，先在 job 裡 build 再搬進 public：

.gitlab-ci.yml · Vite 範例
image: node:20

pages:
  stage: deploy
  script:
    - npm ci
    - npm run build          # 產出 dist/
    - cp -r dist public
  artifacts:
    paths: [public]
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
路徑注意：若 base 路徑不是根目錄，前端資源會 404。 Vite 需設 base: '/project-name/'；Astro 設 site 與 base——這是框架站最常見的坑。

7.5 群組頁 / 使用者頁

  • 使用者頁：建一個名為 USER.gitlab.io 的專案，放 index.html，pipeline 一跑即上線。
  • 群組頁：同理建 GROUP.gitlab.io 專案——可放公司入口、內部文件中心。

7.6 自訂網域與 SSL

在「Deploy → Pages」頁可設定：

  1. Custom domain：填 docs.example.com。
  2. 到 DNS 服務商加 CNAME docs.example.com → USER.gitlab.io。
  3. GitLab 自動申請 Let's Encrypt SSL（勾選 Auto SSL）。
  4. 可設 access control：只有專案成員能看（GitHub 無此功能）。
存取控制是賣點：自架環境的 Pages 可設「登入後才能看」—— 內部文件、暫存站點不用公開給全世界。

7.7 限制 · Limits

項目限制
內容靜態檔案（無後端邏輯）
大小每個 Pages 站有大小上限（視方案）
流量/建置免費方案有流量與 CI 分鐘上限
部署方式一定透過 CI（GitHub 可「deploy from branch」一鍵）

7.8 Worked Example：把這類教學站部署上線

專案結構 · SOURCE
my-docs/
├── index.html
├── docs/
│   └── unit-01.html
├── assets/
│   └── site.css
└── .gitlab-ci.yml

# 注意：資料夾「空目錄」Git 不會追蹤，
# 需放 .gitkeep 或直接在 job 裡 mkdir
部署 · RENDERED

① push → pipeline 啟動
② pages job 執行（複製 public/）
③ artifact 上傳
④ 網址：https://USER.gitlab.io/my-docs/
⑤ 之後每次 push 自動更新網站

7.9 常見錯誤與陷阱

陷阱清單：① job 不叫 pages → 不會發布； ② 內容不在 public/ 或沒用 artifacts 傳出 → 空站； ③ 框架 base 路徑沒設 → 資源 404； ④ rules 條件沒寫 → 每次 push 都部署（非 main 分支也會）； ⑤ 只部署了 main 卻忘了先 merge——先確認分支。

7.10 練習

  • 用純 HTML（index.html + css）部署出你的第一個 Pages 站。
  • 改用 Vite 建置流程，確認資源路徑正確。
  • 嘗試設定自訂網域（可先在本機 /etc/hosts 模擬）。

  • 寫出框架專案（Node build）的 pages job 流程。
